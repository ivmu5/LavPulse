# Двухпоточный анализ очереди

Обычная очередь по-прежнему выбирает один следующий трек за раз. При отсутствии сохранённого анализа декодер читает PCM однократно: основной поток записывает PCM (если нужна предзагрузка) и вычисляет огибающие/ритм; выделенный вспомогательный поток анализирует музыкальную тональность. Четыре блока PCM в очереди, каждый не более 4096 стереокадров float (128 КиБ суммарно полезных данных в очереди), плюс текущие блоки обоих потоков. Буферы ArrayPool, передача владения с копированием, обратное давление при заполнении. После последнего блока основной поток может вычислять сетку одновременно с остатком тонального анализа.

Настройка параллельных задач медиатеки сохраняет число одновременно обрабатываемых треков; ручной массовый анализ использует один вычислительный поток на трек. Дополнительный поток доступен для автоматического анализа и первичной подготовки деки при отсутствии готового анализа, на многопроцессорной системе и при наличии свободного вспомогательного слота. Один такой слот на библиотеку, без ожидания; при занятости последовательный режим. Это не жёсткий глобальный лимит потоков ОС: декодеры, UI, медиатека и аудиовывод имеют свои задачи. Сохранённый анализ используется без повторного вычисления; формат кеша не меняется.

Отмена связывается с жизненным циклом окна. Ошибка потребителя останавливает производителя; ошибка декодера останавливает потребителя; перед освобождением буферов задача потребителя завершается. Ошибки не маскируются отменой, если отмены пользователя не было. На уровне библиотеки анализ и PCM одного локального пути сериализуются даже для разных экземпляров TrackFile; неиспользуемые блокировки освобождаются, ожидание происходит до получения слота декодера. Бесконечные повторы независимой отмены ограничены тремя попытками, завершение без публикации результата также блокирует повтор. 

Исключение обработчика прогресса не прерывает ожидание уже запущенной фоновой задачи.

Тесты сравнивают последовательный/параллельный результат, проверяют исключения обеих сторон, отмену при заполненном буфере, выдачу вспомогательного слота и повтор фоновой задачи. Фактическое ускорение зависит от декодера и процессора; необходимы измерения на Android и Windows. Синхронный вызов системного декодера может завершаться с задержкой при отмене.
