# Rhythm Analyzer V9

## Основание

Три локальных диагностических архива: 14 треков, 1685 ручных отметок. Отмечены четвертной/половинный темп вместо основной доли, ложные доли в ямах, преждевременные границы, исчезновение сетки на слабых атаках. Ручные отметки — ориентир, а не полная разметка. Музыка, архивы и индивидуальные отметки в git не включаются.

## Изменения

- Неизменяемые исходные оценки, отдельный рейтинг для Viterbi и оценка уверенности. Сравнение четверти, половины и удвоения темпа по исходным локальным и глобальным данным, без каскадного продвижения.
- Мягкое предпочтение половинного темпа у быстрых пульсаций при независимом подтверждении; ниже 55 BPM штраф только при наличии сопоставимого более быстрого кандидата. Это эвристика музыкальной интерпретации, не абсолютная граница истинного BPM.
- Слабые окна допускаются только при локальной и общей периодичности и собственной фазовой согласованности. Принимается не только сильная бочка.
- Повторная локальная привязка фазы каждые две секунды с ограниченной коррекцией; начальные и конечные неподтверждённые доли исключаются. Перерыв в подтверждённой сетке остаётся возможным.
- Каждая гипотеза TrackBeatEstimate содержит оценку достоверности, поправку, поддержку атакой, признак провала энергии и подтверждение. Только BeatFrames используются существующими потребителями. Предсказания сохраняются также для полностью отклонённых участков, не обещают непрерывную сетку на всём треке.
- Schema 3: raw-tempo-scores.csv, phase-scores.csv, confidence-scores.csv, beat-evidence.csv; tempo-scores.csv теперь рейтинг, не вероятность. Сохранены остальные CSV.
- analysis-v9: пересчёт анализа после обновления, не удаляет MP3, очередь или директорию PCM.

## Проверка

```powershell
dotnet run --project tests/Laveyana.Audio.Playback.Checks -c Release -- --rhythm-report "C:\Reports\LavPulse_Report_20261126_000458.zip" "C:\Reports\LavPulse_Report_20261126_004350.zip" "C:\Reports\LavPulse_Report_20261126_005225.zip"
```

Проверка выполняет фактический C# анализ на экспортированной 100 Гц огибающей, выводит покрытие, исходное/новое число долей, совпадения 1:1 и гипотезы. Сопоставление 1:1 не является precision/recall для всего трека, поскольку разметка неполная. Проверить помеченные интервалы, темп, отсутствие регрессий, работу PCM/Android отдельно. Исследовательская проверка ранжирования на 14 огибающих не заменяет запуск полной C# регрессии.
